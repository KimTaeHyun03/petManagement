# PawCare 최종 발표 — 슬라이드 구성 & 발표 대본

> **가정**: 발표 12~15분 + 라이브 데모 / 슬라이드 14장 / 발표자 4인 분담
> 각 슬라이드는 **[슬라이드에 담을 내용]** 과 **[발표 멘트(대본)]** 를 나눠서 정리.
> 시간이 모자라면 ▽ 표시된 슬라이드를 합치거나 줄인다.

## 슬라이드 1 — 표지

**[담을 내용]**
- 서비스명 **PawCare** + 슬로건 *"병원을 최대한 적게 가기 위해, 사전에 대비"*
- 한 줄 정의: 사진 한 장으로 끝나는 반려동물 일상 건강 기록 + AI 챗봇 상담
- 팀명 / 팀원 4인 / 발표일

**[발표 멘트]**
> "안녕하세요. 저희 팀은 강아지·고양이 보호자를 위한 반려동물 헬스케어 웹서비스 **PawCare**를 만들었습니다. 핵심 한 줄은 '병원에 가기 전에 미리 대비하자'입니다. 보호자가 영수증이나 사료 성분표 사진 한 장만 올리면, 나머지는 서비스가 자동으로 기록하고 챗봇이 상담해 줍니다."

## 슬라이드 2 — 문제 정의 (왜 만들었나)

**[담을 내용]**
- 반려인의 페인포인트 3가지:
  1. 체중·음식·접종 정보가 **여기저기 흩어져** 통합 관리가 안 됨
  2. 사료 성분표에 위험·알러지 성분이 있어도 **그때그때 일일이 검색하기 번거로움**
  3. 다음 접종일을 **놓치기 쉬움** (특히 광견병 등 법적 의무 백신)
- 결과: 문제를 미리 못 잡고 **병원에 가서야** 알게 됨

**[발표 멘트]**
> "반려동물을 키우다 보면 체중, 먹는 음식, 예방접종 기록이 전부 따로 놉니다. 사료 성분표에 우리 아이한테 위험한 성분이 있는지 매번 검색하기도 번거롭고, 접종일은 놓치기 일쑤죠. 결국 문제가 생기고 나서야 병원에 가게 됩니다. 저희는 이걸 '미리' 잡고 싶었습니다."

---

## 슬라이드 3 — 솔루션 한 장 요약

**[담을 내용]**
- 핵심 플로우 다이어그램 (workflow 0절 그대로):
  ```
  가입·로그인 → 반려동물 등록 → 사진 한 장 업로드
                                   ├ 성분표 OCR → 위험성분·알러지 경고
                                   ├ 영수증 OCR → 예방접종 자동 기록
                                   └ 체중 입력 → 급변 알림
                                          ↓
                              통합 타임라인 / 대시보드
                                          ↓
                              AI 챗봇 — 누적 기록 기반 상담
  ```
- 한 문장: **사진 한 장으로 끝나는 일상 기록 → 타임라인 기반 챗봇 상담**

**[발표 멘트]**
> "전체 흐름은 이렇습니다. 가입하고 반려동물을 등록한 다음, 영수증이나 성분표 사진을 올리면 OCR이 자동으로 분류해서 — 성분표면 위험 성분과 알러지를 경고하고, 영수증이면 예방접종 기록을 자동으로 만들어 줍니다. 체중을 입력하면 급변 시 알림이 가고요. 이 모든 기록이 하나의 타임라인에 시간순으로 쌓이고, 마지막으로 이 누적 데이터를 컨텍스트로 챗봇이 상담을 해줍니다."

---

## 슬라이드 4 — 차별점 3가지 (가장 중요) ★

**[담을 내용]**
1. **OCR 자동 기록** — 폼을 일일이 안 채워도 사진 한 장이면 입력 끝 (Naver CLOVA OCR)
2. **펫 단위 RAG 챗봇** — 단순 GPT가 아니라 *우리 아이의 실제 기록*을 컨텍스트로 주입
3. **의료 안전장치** — AI 진단 금지 / 면책 고지 상시 / 1차 출처 교차검증 / OCR 사용자 확정 후 저장

**[발표 멘트]**
> "다른 서비스와 다른 점 세 가지입니다. 첫째, OCR로 입력 부담을 없앴습니다. 둘째, 챗봇이 그냥 일반 GPT가 아니라 '우리 아이'의 실제 체중·접종·성분표 기록을 컨텍스트로 받아서 답합니다. 셋째, 의료 도메인이라 안전장치를 꼼꼼히 넣었습니다 — AI가 진단·처방은 절대 안 하고, 면책 고지를 항상 띄우고, 데이터도 학회·정부 1차 출처로 교차검증했습니다. 이 세 가지는 뒤에서 자세히 보여드리겠습니다."

---

## 슬라이드 5 — 시스템 아키텍처

**[담을 내용]**
- PLAN 3.1 구조도 (간소화 버전):
  ```
  [React + TS 클라이언트]
        │ HTTPS / JWT
  [Express API]  ── 8개 도메인 서비스
        ├ Auth / Pet / Weight / OCR / Food / Vaccination / Timeline / Chatbot
        ├ 알림 처리기 (node-cron 매일 09시)
        └ 외부연동: CLOVA OCR · OpenAI gpt-4o-mini
  [AWS RDS(PostgreSQL)]  운영DB + 마스터DB(DangerFood/Vaccine/StandardWeight)
  [AWS S3]  OCR 원본 이미지 보관
  ```
- 기술 스택 배지: React 19 · TypeScript · Express · PostgreSQL(RDS) · S3 · CLOVA OCR · OpenAI

**[발표 멘트]**
> "아키텍처입니다. 프론트는 React, 백엔드는 Express로 8개 도메인 서비스를 모듈로 나눴습니다. DB는 AWS RDS PostgreSQL을 쓰고, 운영 데이터와 별도로 위험음식·백신·표준체중 같은 검증된 마스터 데이터를 따로 둡니다. OCR 원본 이미지는 S3에 보관하고, 외부 API는 Naver CLOVA OCR과 OpenAI를 연동했습니다."

## 슬라이드 6 — 데이터 모델 (ERD) ▽

**[담을 내용]**
- 핵심 관계: `User 1—N Pet 1—N { WeightRecord, VaccinationRecord, IngredientScan, ChatLog }`
- 마스터: DangerFood / Vaccine / StandardWeight
- **펫 단위 격리** 강조: 모든 기록이 `pet_id`로 분리, 모든 API에서 사용자-펫 권한 검증

**[발표 멘트]**
> "데이터 구조는 사용자 밑에 여러 펫, 펫 밑에 체중·접종·성분표스캔·챗봇 로그가 달리는 형태입니다. 핵심은 모든 기록이 펫 단위로 분리되고, 모든 API에서 '이 사용자가 이 펫의 주인이 맞는지' 권한을 검증한다는 점입니다. 한 계정으로 여러 마리를 관리해도 데이터가 섞이지 않습니다."

## 슬라이드 7 — 라이브 데모 ① 가입 → 펫 등록 (담당: 김태현)

**[담을 내용]**
- 데모 화면 캡처(백업용 스크린샷도 준비)
- 보여줄 것: 회원가입 → 로그인 → 반려동물 등록(사진 업로드 포함) → 다묘 전환

**[발표 멘트]**
> "이제 실제로 보여드리겠습니다. 회원가입을 하고 — 비밀번호는 안전하게 처리됩니다 — 로그인 후 반려동물을 등록합니다. 이름, 종, 품종, 그리고 알러지 정보를 넣습니다. 이 알러지 정보가 뒤에서 성분표 매칭에 쓰입니다. 사진도 올릴 수 있고요. 여러 마리를 등록하면 상단에서 전환할 수 있습니다."

---

## 슬라이드 8 — 라이브 데모 ② OCR (담당: 장윤서) ★

**[담을 내용]**
- 성분표 사진 업로드 → 위험성분 + 알러지 경고 카드
- (가능하면) 영수증 사진 업로드 → 접종 후보 자동 생성 → 사용자 확정
- 강조: **자동 저장이 아니라 사용자가 확인하고 확정**

**[발표 멘트]**
> "OCR 데모입니다. 사료 성분표를 찍어 올리면 CLOVA OCR이 텍스트를 뽑고, 키워드로 '성분표'라고 분류합니다. 그리고 위험음식 DB와 매칭해서 '양파 분말이 들어있다'고 경고하고, 동시에 이 아이의 등록된 알러지와도 매칭해서 맞춤 경고를 띄웁니다. 중요한 건 OCR이 틀릴 수 있으니 자동 저장하지 않고, 사용자가 확인한 뒤 확정하는 흐름이라는 점입니다."

---

## 슬라이드 9 — 라이브 데모 ③ 체중 + 타임라인 (담당: 김기연)

**[담을 내용]**
- 체중 입력 → ±10% 급변 판정 → 알림
- 표준 체중표 비교 → 정상/과체중/저체중 판정
- 통합 타임라인: 접종·체중·OCR 이벤트가 시간순 한 화면에

**[발표 멘트]**
> "체중을 입력하면 직전 기록 대비 10% 이상 변하면 급변으로 잡아 알림을 보내고, 품종별 표준 체중표와 비교해 정상·과체중·저체중을 판정합니다. 그리고 이 모든 기록 — 접종, 체중, 성분표 스캔 — 이 하나의 타임라인에 시간순으로 쌓입니다. 보호자는 이 한 화면에서 우리 아이의 건강 흐름을 한눈에 봅니다."

## 슬라이드 10 — 라이브 데모 ④ 예방접종 + 알림 (담당: 김찬영)

**[담을 내용]**
- 접종 이력 입력(수동 / 영수증 OCR)
- 다음 권장일 자동 계산 → D-7/D-1/D-day 이메일 알림 (node-cron 매일 09시)
- 광견병 등 법적 의무 백신 강조 표시

**[발표 멘트]**
> "예방접종은 직접 입력하거나 병원 영수증 OCR로 자동 기록됩니다. 접종을 완료하면 다음 권장일을 자동으로 계산해서, D-7·D-1·당일에 이메일로 알림을 보냅니다. 매일 아침 9시에 스케줄러가 돌면서 체크하고요. 특히 광견병처럼 법적 의무인 백신은 따로 강조해서 보여줍니다."

## 슬라이드 11 — 라이브 데모 ⑤ 챗봇 (담당: 김태현) ★

**[담을 내용]**
- 실제 질문 예시: *"최근 한 달 우리 몽이 체중 어땠어?"* / *"다음 접종 뭐 남았어?"*
- 강조: 답변이 **실제 DB 기록 기반** (체중 추이·접종 이력·표준 일정 주입)
- 면책 고지가 답변 끝에 항상 붙음

**[발표 멘트]**
> "마지막으로 챗봇입니다. '최근 한 달 체중 어땠어?'라고 물으면, 일반적인 GPT 답변이 아니라 실제로 이 아이의 체중 기록을 모두 읽어서 증가·감소 흐름을 짚어 답합니다. '다음 접종 뭐 남았어?'라고 물으면 완료한 접종 이력과 표준 일정을 대조해서 알려줍니다. 그리고 모든 답변 끝에는 '참고용이며 정확한 진단은 수의사에게'라는 면책 고지가 항상 붙습니다. AI는 절대 진단하지 않습니다."

## 슬라이드 12 — 기술적 도전 & 해결 ★

**[담을 내용]** (3개만 골라 깊게)
1. **챗봇 컨텍스트 정확도** — GPT가 백신명을 멋대로 바꾸는 문제 → 시스템 프롬프트로 "DB 마스터 명칭 그대로" 강제 + 컨텍스트에 표준 일정 주입
2. **OCR 오인식 리스크** — 의료 기록이라 자동 저장 위험 → "사용자 확정 후 저장" 단계 도입
3. **의료 정보 신뢰성** — 시드 데이터를 KASA·AVMA·ASPCA·검역본부 1차 출처 + 2개 이상 교차검증한 것만 등재

**[발표 멘트]**
> "기술적으로 어려웠던 점 세 가지입니다. 첫째, 챗봇이 백신 이름을 임의로 바꿔 말하는 문제가 있어서, 시스템 프롬프트로 'DB에 있는 명칭만 쓰라'고 강제하고 표준 일정을 컨텍스트로 직접 넣었습니다. 둘째, OCR이 틀리면 잘못된 의료 기록이 남으니 항상 사용자 확정 단계를 거치게 했습니다. 셋째, 잘못된 의료 정보는 곧 동물의 건강 위험이라, 위험음식·백신 데이터는 학회와 정부 자료 두 곳 이상에서 교차검증한 것만 넣었습니다."

## 슬라이드 14 — 향후 계획 & 마무리

**[담을 내용]**
- **의도적 1차 제외 범위** (책임 회피가 아니라 설계 결정임을 강조):
  - 위험도 점수 엔진 (음식·체중·접종 종합 점수)
  - 증상 입력 → 질환 매핑 (의료 진단 책임 영역)
  - 웹 푸시 알림, MFA, 다국어
- **운영 전환 시**: 인증 Refresh Rotation 도입, OCR 정확도 고도화
- 마무리 한 줄: *"병원에 가기 전에, 미리 대비한다"*

**[발표 멘트]**
> "끝으로 향후 계획입니다. 위험도 점수 엔진이나 증상 진단 같은 기능은 일부러 1차 범위에서 뺐습니다 — 의료 진단 책임은 저희가 질 영역이 아니기 때문입니다. 대신 운영 단계로 가면 인증 보안을 강화하고 OCR 정확도를 더 높일 계획입니다. 저희 PawCare는 '병원에 가기 전에 미리 대비한다'는 한 가지 목표에 집중했습니다. 감사합니다."

## 데모 진행 팁 (발표 전 체크리스트)

- [ ] 데모 계정에 **미리 데이터를 채워둘 것** (체중 5개 이상, 접종 2~3건, 성분표 스캔 1~2건) — 빈 화면이면 챗봇·타임라인이 밋밋함
- [ ] 챗봇 질문은 **답이 잘 나오는 것으로 미리 테스트** (체중 추이, 다음 접종)
- [ ] OCR 데모용 **성분표·영수증 이미지 준비** (잘 인식되는 깨끗한 샘플)
- [ ] 네트워크 끊김 대비 **모든 데모 화면 스크린샷/녹화 백업**
- [ ] CLOVA OCR / OpenAI API **키 한도·과금 상태 확인**
