## P2 — 왜 PawCare인가? (발표자: 김태현)

**[담을 내용]**
- 반려 양육 인구의 지속 증가 → 건강 관리 수요 동반 증가
- 치료보다 '예방' 중심으로 — 이상 신호를 일찍 잡으면 큰 병·비용을 줄임
- 사후 대응 → 사전 대비로 전환
- 슬로건: "병원에 가기 전에, 미리 대비한다"

**[발표 멘트]**
> "먼저 왜 만들었는지입니다. 반려동물을 가족처럼 키우는 인구가 계속 늘면서 건강 관리 수요도 같이 커지고 있습니다. 그런데 중요한 건 치료보다 '예방'입니다. 이상 신호를 일찍 알아채면 큰 병과 비용을 줄일 수 있죠. 저희는 문제가 생긴 뒤 대응하는 게 아니라, 그 전에 데이터로 미리 대비하자는 데서 출발했습니다."

## P3 — 기존 서비스의 한계 (발표자: 김태현)

**[담을 내용]**
- **흩어진 기록** — 체중·음식·접종 정보가 앱마다 따로 놀아 통합 관리가 안 됨
- **번거로운 검색** — 사료 성분의 위험 여부를 매번 직접 검색해야 함
- **놓치는 접종일** — 광견병 등 법적 의무 백신조차 일정을 놓치기 쉬움

**[발표 멘트]**
> "기존 방식의 한계는 세 가지입니다. 첫째, 체중·음식·접종 기록이 전부 따로 놀아서 통합 관리가 안 됩니다. 둘째, 사료 성분표에 위험한 게 있는지 매번 직접 검색해야 하니 번거롭습니다. 셋째, 접종일은 놓치기 쉽죠. 특히 광견병처럼 법적 의무인 백신조차요. 결국 문제를 미리 못 잡고 병원에 가서야 알게 됩니다."

## P10 — 펫별 맞춤 RAG 챗봇 (발표자: 김태현)

**[담을 내용]**
- 펫 DB를 주입한 RAG — 실제 기록 기반 답변
- gpt-4o-mini로 맞춤 상담 생성
- 면책 고지 상시(진단 아님 · 수의사 안내)

**[발표 멘트]**
> "마지막 핵심 기능은 챗봇입니다. 일반 GPT가 아니라, '우리 아이'의 실제 체중·접종·성분표 기록을 컨텍스트로 받아서 답하는 RAG 방식입니다. '최근 한 달 체중 어땠어?'라고 물으면 실제 기록을 읽어 증가·감소 흐름을 짚어 주고, '다음 접종 뭐 남았어?'라고 물으면 이력과 표준 일정을 대조해 알려줍니다. 그리고 모든 답변 끝에는 '진단이 아니라 참고용이며 정확한 건 수의사에게'라는 고지가 항상 붙습니다."

## P11 — 기술 스택 및 시스템 구성 (발표자: 김찬영)

**[담을 내용]**
- React + TypeScript 클라이언트 — (HTTPS·JWT) → Express API(8개 도메인 서비스)
- PostgreSQL(AWS RDS) 운영DB + 마스터DB / AWS S3 OCR 원본 이미지
- 스택: React 19 · TypeScript · Express · PostgreSQL·RDS · S3 · CLOVA OCR · OpenAI

**[발표 멘트]**
> "전체 구조입니다. 프론트는 React와 TypeScript, 백엔드는 Express로 8개 도메인 서비스를 모듈로 나눴고, 통신은 HTTPS와 JWT로 합니다. DB는 AWS RDS의 PostgreSQL을 쓰고, 운영 데이터와 별도로 위험음식·백신·표준체중 같은 검증된 마스터 데이터를 따로 둡니다. OCR 원본 이미지는 S3에 보관하고요. 인프라와 배포는 제가 맡아 구성했습니다."

## P14 — 향후 개선 방향 (발표자: 김찬영) ▽
