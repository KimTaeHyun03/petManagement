## P2 — 왜 PawCare인가? (발표자: 김태현)

**[담을 내용]**
- 반려 양육 인구의 지속 증가 → 건강 관리 수요 동반 증가
- 치료보다 '예방' 중심으로 — 이상 신호를 일찍 잡으면 큰 병·비용을 줄임
- 사후 대응 → 사전 대비로 전환
- 슬로건: "병원에 가기 전에, 미리 대비한다"

**[발표 멘트]**
> "먼저 왜 만들었는지입니다. 반려동물을 가족처럼 키우는 인구가 계속 늘면서 건강 관리 수요도 같이 커지고 있습니다. 그런데 중요한 건 치료보다 '예방'입니다. 이상 신호를 일찍 알아채면 큰 병과 비용을 줄일 수 있죠. 문제를 미리 알아채고 예방하자는 의미에서 만들게되었습니다"

## P3 — 기존 서비스의 한계 (발표자: 김태현)

**[담을 내용]**
- **흩어진 기록** — 체중·음식·접종 정보가 앱마다 따로 놀아 통합 관리가 안 됨
- **번거로운 검색** — 사료 성분의 위험 여부를 매번 직접 검색해야 함
- **놓치는 접종일** — 광견병 등 법적 의무 백신조차 일정을 놓치기 쉬움

**[발표 멘트]**
> "기존 서비스의 한계는 크게 세 가지입니다. 먼저 체중·음식·접종 기록이 전부 따로 놀아서 통합 관리가 어렵습니다. 두번째로 사료 성분표에 위험한 게 있는지 매번 검색해야 하니 번거롭습니다. 마지막으로 예방접종일을 놓치기 쉽다는 점이 있습니다"

## P5 — 찍으면 끝, OCR 자동 기록 (발표자: 장윤서)

**[발표 멘트]**

## P6 — 위험 성분 및 알러지 사전 차단 (발표자: 장윤서)

**[담을 내용]**
- 성분표 분석 결과 카드: 위험 성분 N건 + 우리 아이 알러지 일치 N건
- 위험음식 DB 대조 + 펫 알러지 매칭 / 출처: ASPCA 1차 자료
- "참고용이며 진단이 아닙니다" 면책 고지

**[발표 멘트]**
> "성분표를 분석하면 두 가지를 동시에 봅니다. 하나는 위험음식 DB와 대조해  위험한 성분을 잡아내는 것, 다른 하나는 해당 동물에 등록된 알러지와 매칭해 맞춤 경고를 띄우는 겁니다. 데이터는 ASPCA 같은 1차 출처를 기준으로 했습니다"

## P10 — 펫별 맞춤 RAG 챗봇 (발표자: 김태현)

**[담을 내용]**
- 펫 DB를 주입한 RAG — 실제 기록 기반 답변
- gpt-4o-mini로 맞춤 상담 생성
- 면책 고지 상시(진단 아님 · 수의사 안내)

**[발표 멘트]**
> "마지막 핵심 기능은 챗봇입니다. 일반 GPT가 아니라, 해당 펫의 실제 체중·접종·성분표 기록을 컨텍스트로 받아서 답하는 RAG 방식입니다. '체중 변화 추이를 보여줘'라고 말하면 실제 기록을 읽어 증가·감소 흐름을 짚어 주고, '다음 접종 뭐 남았어?'라고 물으면 이력과 표준 일정을 대조해 알려줍니다.

## P11 — 기술 스택 및 시스템 구성 (발표자: 김찬영)

**[담을 내용]**
- React + TypeScript 클라이언트 — (HTTPS·JWT) → Express API(8개 도메인 서비스)
- PostgreSQL(AWS RDS) 운영DB + 마스터DB / AWS S3 OCR 원본 이미지
- 스택: React 19 · TypeScript · Express · PostgreSQL·RDS · S3 · CLOVA OCR · OpenAI

**[발표 멘트]**
> "전체 구조입니다. 프론트는 React와 TypeScript, 백엔드는 Express로 8개 도메인 서비스를 모듈로 나눴고, 통신은 HTTPS와 JWT로 합니다. DB는 AWS RDS의 PostgreSQL을 쓰고, 운영 데이터와 별도로 위험음식·백신·표준체중 같은 검증된 마스터 데이터를 따로 둡니다. OCR과 반려동물 프로필 원본 이미지는 S3에 보관하고요."

## P12 — PawCare만의 차별성 (발표자: 김태현) ★

**[담을 내용]**

- **확산 가능성** — 8개 도메인 모듈 구조로 기능 확장이 쉬운 설계

**[발표 멘트]**
> "다른 서비스와 다른 점은 크게 세 가지입니다. 첫째 지속가능성 — ocr자동기록으로 수기 입력의 불편함을 개선하여 장기 사용이 편리하고 기록이 쌓일수록 컨텍스트가 풍부해져 챗봇 답변의 품질이 향상됩니다. 둘째 접근성 — 웹기반으로 설치없이 사용이 가능하고 일반 챗봇과 달리 기록만 해두면 맞춤형 답변을 제공합니다. 셋째 확산 가능성 — 8개 도메인을 모듈로 나눠서 기능을 덧붙이기 쉬운 구조로 설계했습니다."

## 발표 전 체크리스트

- [ ] 데모/스크린샷 계정에 **데이터를 미리 채워둘 것** (체중 5개 이상, 접종 2~3건, 성분표 스캔 1~2건) — 빈 화면이면 타임라인·챗봇이 밋밋함
